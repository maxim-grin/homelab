# CI on GitHub Actions

## Goal

Run the repository's checks on GitHub for every pull request and every push
to `main`, and make them required to merge. Today nothing runs them
automatically: `.pre-commit-config.yaml` executes locally only, so
`--no-verify` or a fresh clone skips it, and nothing runs
`terraform validate`, `kustomize build` or `helm template` at all.

Merge to `main` is the deploy (ArgoCD syncs `main`), so the point of CI is to
catch, before merge, what would otherwise break in ArgoCD or leak a secret.

## Non-goals

- No deploy, no `terraform plan`/`apply`, no cluster or Proxmox access.
- No secrets in CI: no vault password, no tfvars, no kubeconfig.
- `proxmox/environments/prod` and `talos/` are never-applied scaffolding and
  are not validated.
- Branch protection is not configured by this change. It is documented and
  left to the repository owner.

## Workflow

`.github/workflows/ci.yaml`

- Triggers: `pull_request` and `push` to `main`. No path filters: a
  path-filtered workflow that is skipped leaves its required check pending
  forever and blocks merge.
- `permissions: contents: read`. `concurrency` cancels superseded PR runs.
- Actions pinned by commit SHA; tool versions pinned.
- Four parallel jobs. Their names are the required checks: `pre-commit`,
  `commits`, `terraform`, `manifests`.

### `pre-commit`

`pre-commit run --all-files`, using the repo's own config as the single
source of truth (whitespace, check-yaml, detect-private-key, gitleaks,
ansible-lint, terraform fmt). The runner needs terraform, Python,
ansible-lint and the collections pinned in `ansible/requirements.yml`,
because ansible-lint and terraform-fmt are `language: system` hooks.
ansible-lint runs at profile `production` with no ignore file, so any
finding fails the job. Checkout uses `fetch-depth: 0`
for gitleaks. ansible-lint performs its own syntax-check; a separate
`ansible-playbook --syntax-check` is not run because it needs
`secret.yaml`'s vault password.

### `commits` (pull requests only)

Runs `conventional-pre-commit` over each non-merge commit subject in
`base..head`. Skipped on push to `main`, where GitHub's
`Merge pull request #N` commits would fail the convention.

### `terraform`

In `proxmox/environments/dev`: `terraform init -backend=false`,
`terraform validate`, and `tflint` (config in `.tflint.hcl`). Formatting is
already covered by `pre-commit`.

### `manifests`

Runs `scripts/check-manifests.sh`, which is also the local verification
command:

1. `kustomize build` for every directory containing a `kustomization.yaml`.
2. `helm template` for every Helm source found in
   `argocd/environments/dev/applications/`. Chart, repository and version
   come from the Application CR (via `yq`); values come from the matching
   `argocd/apps/*/dev/values.yaml`.
3. `kubeconform -strict` over all rendered output plus `argocd/base/` and the
   Application CRs, with CRD schemas from the datreeio CRDs catalog.

`<path:...>` AVP placeholders are strings and pass schema validation. If one
appears in a non-string field, the script substitutes a placeholder for that
field only; this is settled on the first real run.

## Rollout

1. Run every check locally against `main` to get a baseline. Failures that
   exist today are fixed, not ignored, so the CI PR starts green. The
   ansible-lint findings and deprecations were cleared in PR #27 (merged);
   the trailing-whitespace debt in an old plan file is fixed by the first
   commit of this branch. Any further non-trivial fix goes in its own PR.
2. Merge the CI PR. The repository owner merges; the agent stops at the open
   PR.
3. Owner enables branch protection on `main` with the four checks required.
   Doing this before `main` is green would block the CI PR itself.

## Verification

Run `scripts/check-manifests.sh`, `pre-commit run --all-files`, and the
terraform commands locally; then confirm on the real Actions run that each
job's log shows the tools executing, not just a green status.
