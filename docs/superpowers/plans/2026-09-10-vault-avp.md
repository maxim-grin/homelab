# Vault and argocd-vault-plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up HashiCorp Vault on its own VM outside the cluster, and have argocd-vault-plugin render the jobboard Secrets from it so nothing is applied by hand.

**Architecture:** Vault runs on a Proxmox VM so it survives cluster rebuilds and can serve the secrets a rebuild consumes. Its KV seed lives in `ansible/secret.yaml` under `vault_kv`, so no second encryption system is introduced. AVP runs as a CMP sidecar in `argocd-repo-server`; the `cmp-plugin` ConfigMap and `argocd-vault-plugin-config` Secret are created by Ansible **before** the Helm deploy, which is what stops the failure that wedged repo-server last time.

**Tech Stack:** Terraform `telmate/proxmox` 3.0.2-rc10, Ansible with `kubernetes.core`, HashiCorp Vault (apt, file storage), argocd-vault-plugin, ArgoCD Helm chart v8.6.3.

**Spec:** `docs/superpowers/specs/2026-09-10-vault-avp-design.md` (Layers 1, 2, 3, the Survival model, Sharp edges, and their entries in Documentation changes)

**Order:** Land `2026-09-10-argocd-selfmanagement-ingress.md` FIRST. Task 5 here
adds a `repoServer` key to the `argocd_helm_values` dict that plan creates. This
plan is a prerequisite for `2026-09-10-image-updater.md`.

## Global Constraints

- **ArgoCD syncs `main` from GitHub, not the working copy.** A commit is not a deploy.
- Branch before the first commit. `main` receives finished work as a merge.
- Conventional Commits. Subject <= 50 chars, imperative, lowercase, no trailing period. Body wrapped at 72. Types: `feat`, `fix`, `refactor`, `docs`, `chore`, `ops`.
- **No `Co-Authored-By` trailer and no generated-with footer.**
- **`ubuntu-cid-tp` must exist before any `terraform apply`.** Every VM is a `full_clone` of it.
- **`disk_size` only goes up.** Shrinking fails with `can't unplug bootdisk 'scsi0'` *and* writes the smaller value into `terraform.tfstate`. Repair is `terraform apply -refresh-only`.
- **Resource pools are not created by Terraform.** Use the existing `VM` pool, which already has the `TerraformProv` ACL. A new pool needs `TerraformProv` granted on `/pool/<name>` by hand.
- **The Vault root token and unseal key are never written to `secret.yaml`, never defaulted in a role, and never captured by a playbook.** Tasks that need the root token take it per-run as `-e vault_token=...`.
- `ansible-lint` runs at the **production** profile: FQCNs required, `true`/`false` not `yes`/`no`.
- ArgoCD reads a **public** repository. `<path:...>` placeholders are committed; values never are.
- No test suite. Verification is tool checks plus inspecting the cluster.
- Steps marked **[operator]** need Proxmox, cluster, or password-manager access an agent does not have.

```hcl
################################################################################
# HashiCorp Vault
################################################################################
module "vault" {
  source = "../../modules/ubuntu-vm"

  # Basic VM Configuration
  vm_name     = "vault"
  vmid        = 104
  target_node = var.pm_target_node
  # Existing pool on purpose: Terraform does not create pools, and
  # terraform@pve needs TerraformProv granted on /pool/<name> by hand before
  # placement into a new one works at all.
  pool = "VM"

  clone_template = var.clone_template_ubuntu
  full_clone     = true

  # Resource Allocation
  # A file-backed Vault with a handful of KV paths needs almost nothing.
  memory    = 2048
  cpu_cores = 2

  disk_size    = "20G"
  disk_storage = "local-lvm"

  # First up, ahead of nfs-01 at order=10. Vault is the root of trust: when
  # it is sealed or absent, argocd-vault-plugin renders nothing and every
  # Application carrying a <path:...> placeholder fails to sync.
  start_at_node_boot = true
  startup            = "order=5,up=20"

  # Qemu Agent
  qemu_agent = 1

  # Network Configuration
  network_firewall = true
  ip_config        = format("ip=%s,gw=%s", var.vault_vm_ip, var.gateway)
  vm_ip            = split("/", var.vault_vm_ip)[0]

  # Cloud-init Settings
  ci_user              = var.ci_user
  ci_password          = var.ci_password
  ssh_private_key_path = var.ssh_private_key_path
  ssh_public_key       = var.ssh_public_key

  # OS configuration lives in the ansible/ vault role.
  enable_provisioners = false

  # Tags
  tags = "ubuntu,vault,dev"
}
```

```yaml
- name: Install prerequisites
  ansible.builtin.apt:
    name:
      - gpg
      - coreutils
    state: present
    update_cache: true

- name: Download the HashiCorp GPG key
  ansible.builtin.get_url:

    mode: "0644"

- name: Dearmor the HashiCorp GPG key
  ansible.builtin.command:
    cmd: gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg /tmp/hashicorp.asc
    creates: /usr/share/keyrings/hashicorp-archive-keyring.gpg

- name: Add the HashiCorp repository
  ansible.builtin.apt_repository:
    repo: >-
      deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg]
      https://apt.releases.hashicorp.com {{ ansible_distribution_release }} main
    state: present

- name: Install Vault
  ansible.builtin.apt:
    name: vault
    state: present
    update_cache: true

- name: Create the Vault directories
  ansible.builtin.file:
    path: "{{ item }}"
    state: directory
    owner: vault
    group: vault
    mode: "0755"
  loop:
    - "{{ vault_config_dir }}"
    - "{{ vault_data_dir }}"

- name: Render the Vault configuration
  ansible.builtin.template:
    src: vault.hcl.j2
    dest: "{{ vault_config_dir }}/vault.hcl"
    owner: vault
    group: vault
    mode: "0640"
  notify: Restart vault

- name: Enable and start Vault
  ansible.builtin.systemd_service:
    name: vault
    enabled: true
    state: started
    daemon_reload: true
```

- [ ] **Step 4: Write the seed tasks**

`ansible/roles/vault/tasks/seed.yaml`:

```yaml
---
- name: Require a Vault token
  ansible.builtin.assert:
    that:
      - vault_token is defined
      - vault_token | length > 0
    fail_msg: >-
      Pass the Vault root token for this run: -e vault_token=...
      It is deliberately absent from secret.yaml and from role defaults.

- name: Enable the KV v2 secrets engine
  ansible.builtin.uri:
    url: "http://{{ ansible_default_ipv4.address }}:{{ vault_api_port }}/v1/sys/mounts/secret"
    method: POST
    headers:
      X-Vault-Token: "{{ vault_token }}"
    body_format: json
    body:
      type: kv
      options:
        version: "2"
    status_code: [204, 400]
  register: vault_kv_mount
  changed_when: vault_kv_mount.status == 204
  # 400 is "path is already in use", which is success on a re-run.

- name: Seed the KV paths
  ansible.builtin.uri:
    url: >-
      http://{{ ansible_default_ipv4.address }}:{{ vault_api_port }}/v1/secret/data/{{ item.key }}
    method: POST
    headers:
      X-Vault-Token: "{{ vault_token }}"
    body_format: json
    body:
      data: "{{ item.value }}"
    status_code: 200
  loop: "{{ vault_kv | dict2items }}"
  loop_control:
    label: "{{ item.key }}"
  no_log: true
```

`no_log: true` matters: without it the secret values land in the playbook output.

### Task 4: Kubernetes auth from outside the cluster

**Files:**
- Create: `ansible/roles/vault/tasks/k8s_auth.yaml`
- Modify: `ansible/roles/vault/tasks/main.yaml`
- Create: `argocd/base/vault-auth-delegator.yaml`
- Modify: `argocd/base/kustomization.yaml` if one exists, otherwise leave `argocd/base/` as a plain directory

**Interfaces:**
- Consumes: `vault_token` per-run; the cluster CA certificate and a token-reviewer JWT, both read from the control plane.
- Produces: Vault auth role `argocd`, bound to ServiceAccount `argocd-repo-server` in namespace `argocd`, granting policy `argocd-read` over `secret/data/*`. Task 5's `argocd-vault-plugin-config` Secret names this role.

**This is the sharpest edge in the design.** Vault runs outside the cluster, so
it cannot use the in-cluster ServiceAccount shortcut. It needs
`disable_local_ca_jwt=true`, the cluster CA, and a long-lived reviewer JWT.
Expect the debugging time here. The documented fallback, if it proves
unworkable, is a static Vault token in the AVP config Secret — simpler, but a
real credential recreated by hand at every rebuild, which is the problem AVP
exists to remove. Take the fallback only after this task has genuinely failed,
and record the decision in the spec.

- [ ] **Step 1: Create the token reviewer ServiceAccount**

`argocd/base/vault-auth-delegator.yaml`:

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: vault-auth
  namespace: argocd
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: vault-auth-delegator
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: system:auth-delegator
subjects:
  - kind: ServiceAccount
    name: vault-auth
    namespace: argocd
---
apiVersion: v1
kind: Secret
metadata:
  name: vault-auth-token
  namespace: argocd
  annotations:
    kubernetes.io/service-account.name: vault-auth
# Kubernetes 1.24+ stopped minting ServiceAccount token Secrets
# automatically. Vault needs a token that does not expire, so this one is
# requested explicitly rather than projected with a TTL.
type: kubernetes.io/service-account-token
```

This lands in `argocd/base/`, which the `argocd-config` Application from the
self-management plan already syncs. Push it and let ArgoCD apply it.

- [ ] **Step 3: Write the auth-configuration tasks**

`ansible/roles/vault/tasks/k8s_auth.yaml`:

```yaml
---
- name: Require a Vault token
  ansible.builtin.assert:
    that:
      - vault_token is defined
      - vault_token | length > 0
    fail_msg: "Pass the Vault root token for this run: -e vault_token=..."

- name: Read the cluster CA certificate
  ansible.builtin.slurp:
    src: /etc/kubernetes/pki/ca.crt
  delegate_to: "{{ groups['k8s_control_plane'][0] }}"
  register: vault_k8s_ca

- name: Read the token reviewer JWT
  ansible.builtin.command:
    cmd: >-
      kubectl --kubeconfig /etc/kubernetes/admin.conf -n argocd
      get secret vault-auth-token -o jsonpath={.data.token}
  delegate_to: "{{ groups['k8s_control_plane'][0] }}"
  become: true
  register: vault_k8s_jwt
  changed_when: false

- name: Enable the kubernetes auth method
  ansible.builtin.uri:
    url: "http://{{ ansible_default_ipv4.address }}:{{ vault_api_port }}/v1/sys/auth/kubernetes"
    method: POST
    headers:
      X-Vault-Token: "{{ vault_token }}"
    body_format: json
    body:
      type: kubernetes
    status_code: [204, 400]
  register: vault_k8s_auth
  changed_when: vault_k8s_auth.status == 204

- name: Configure the kubernetes auth method
  ansible.builtin.uri:
    url: "http://{{ ansible_default_ipv4.address }}:{{ vault_api_port }}/v1/auth/kubernetes/config"
    method: POST
    headers:
      X-Vault-Token: "{{ vault_token }}"
    body_format: json
    body:
      kubernetes_host: "https://{{ host_ips['master-01'] }}:6443"
      kubernetes_ca_cert: "{{ vault_k8s_ca.content | b64decode }}"
      token_reviewer_jwt: "{{ vault_k8s_jwt.stdout | b64decode }}"
      # Vault is not running in the cluster, so there is no local
      # ServiceAccount token for it to fall back on. Without this it tries
      # one anyway and fails with a message that does not say so.
      disable_local_ca_jwt: true
    status_code: 204
  no_log: true

- name: Write the argocd-read policy
  ansible.builtin.uri:
    url: "http://{{ ansible_default_ipv4.address }}:{{ vault_api_port }}/v1/sys/policies/acl/argocd-read"
    method: PUT
    headers:
      X-Vault-Token: "{{ vault_token }}"
    body_format: json
    body:
      policy: |
        path "secret/data/*" {
          capabilities = ["read"]
        }
        path "secret/metadata/*" {
          capabilities = ["list", "read"]
        }
    status_code: 204

- name: Bind the argocd role to the repo-server ServiceAccount
  ansible.builtin.uri:
    url: "http://{{ ansible_default_ipv4.address }}:{{ vault_api_port }}/v1/auth/kubernetes/role/argocd"
    method: POST
    headers:
      X-Vault-Token: "{{ vault_token }}"
```
