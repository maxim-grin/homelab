# Operator Runbooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One runbook set under `docs/runbooks/` holding every operator
command, kept current by a drift-guard script in pre-commit and CI.

**Architecture:** Four area files plus an index, each entry in one shape
(when, one copy-paste block, `Expect:`, `If not:`). `scripts/check-runbooks.sh`
fails on an unlisted playbook, a command naming a missing playbook or
inventory, or a broken relative link. Documents and one shell script only; no
playbook or Terraform behaviour changes.

**Tech Stack:** Markdown, bash, shellcheck, pre-commit, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-04-runbooks-design.md`

## Global Constraints

- Playbooks run from `ansible/` with `-e @secret.yaml --ask-vault-pass`; default
  inventory is `inventories/dev`, so shared and prod always need `-i`.
- `$DEV_KC` and `$PROD_KC` are the kubeconfig paths. Vault uses `VAULT_ADDR`
  plus `read -rs VAULT_TOKEN`, then `unset`. No secret value is ever written
  in a runbook (CLAUDE.md "Secrets"); only where it comes from.
- A `<placeholder>` is explained on the line above its command.
- Every command is copied from its owning file (playbook header, role
  defaults, `rebuild.md`, `operations.md`) and re-checked against merged
  files. Never from memory.
- Commit style per CLAUDE.md: Conventional, subject ≤ 50, lowercase,
  imperative; **no `Co-Authored-By` trailer**. Branch `runbooks-design`
  (already has `main` merged in, post #86 to #89). Never `--no-verify`.
- Out of scope: `justfile`, editing `rebuild.md` / `ansible/README.md` /
  historical specs, plans, ADRs, changing any playbook or script behaviour.

## Review Focus

- Playbook added later with no runbook row: guard names the file.
- `ansible-playbook` command wrapped across lines with `\`: guard must join
  continuations before parsing, else it misses the playbook name.
- Command inside a fenced block vs. prose mention of a playbook: only fenced
  `ansible-playbook` lines are parsed; prose is not a failure.
- `-i inventories/shared -i inventories/dev` (two `-i`): both checked.
- Relative link with an `#anchor`, and a link to a directory: anchor stripped,
  directory accepted; `http(s)://` and `mailto:` skipped.
- Runbook block that prints a secret (`vault kv get` without `-field` piped to
  nothing, `cat` of a kubeconfig): reviewer greps for it in Task 6.
- `jobboard` `tools/db-backup.sh` was not found in this repo
  (`find . -name db-backup.sh` empty): Task 5 must locate its real home before
  writing the entry, not copy the spec's path.

### Task 1: Drift guard with fixture tests

**Files:**
- Create: `scripts/check-runbooks.sh`
- Create: `scripts/tests/check-runbooks.test.sh`
- Create: `scripts/tests/fixtures/runbooks/` (small fake tree: `ok/`, plus one broken variant per check)

**Interfaces:**
- Produces: `scripts/check-runbooks.sh [root]` — `root` defaults to the repo
  root; reads `<root>/docs/runbooks/*.md` and `<root>/ansible/playbooks/`,
  `<root>/ansible/inventories/`. Exit 0 clean; exit 1 printing one line per
  failure, `file: reason`. Mirrors the `[arg]` override style of
  `scripts/check-talos-pins.sh`.

- [ ] **Step 1:** Build the `ok/` fixture (one playbook, one inventory, a
  runbook naming it with a wrapped command and a valid relative link) and one
  broken fixture per check: unlisted playbook, missing playbook in a command,
  missing `-i` inventory, broken link. Test script runs the guard on each,
  asserting exit code and that the message names the culprit. Model on
  `scripts/tests/pve-bootstrap.test.sh`.
- [ ] **Step 2:** Run `scripts/tests/check-runbooks.test.sh`.
  Expected: fails (guard does not exist).
- [ ] **Step 3:** Implement the guard to cover the three spec checks and the
  Review Focus parsing rules (continuations, fenced only, multiple `-i`,
  anchors, directories, external links skipped). `set -euo pipefail`, shellcheck clean.
- [ ] **Step 4:** Run the test script.
  Expected: every case passes, including `ok/` exit 0.
- [ ] **Step 5:** `shellcheck scripts/check-runbooks.sh scripts/tests/check-runbooks.test.sh`.
  Expected: no output. Do not wire into pre-commit or CI yet (the real tree
  has no runbooks, so the hook would block every commit).
- [ ] **Step 6:** Commit `feat: add runbook drift guard`.
