# Dev Spoke Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking. Per CLAUDE.md, this plan
> records decisions, files, order and checks, not finished code: the
> implementer writes the code. Exact values stay verbatim.

**Goal:** Dev becomes a spoke of prod's ArgoCD, adopted in place, and is
rebuildable from scratch with one Terraform apply, one bootstrap playbook
and one registration playbook.

**Architecture:** Prod's existing `apps` ApplicationSet (ADR 0026) gains
dev entries: `- env: dev` in each app's `config.yaml`, generating
`dev-<dir>` from `argocd/apps/<dir>/dev`. Dev's live resources are adopted,
not recreated; dev's own ArgoCD is then uninstalled. Dev's Prometheus runs
in agent mode and remote-writes to prod. Series A converts dev in place;
series B rebuilds it.

**Tech Stack:** ArgoCD ApplicationSets, argocd-vault-plugin (AVP),
kustomize `helmCharts:`, kube-prometheus-stack, Terraform
(`telmate/proxmox` 3.0.2-rc10, native `terraform test`), Ansible, kubeadm,
Vault.

**Spec:** [2026-10-05-dev-spoke-design.md](../specs/2026-10-05-dev-spoke-design.md)

## Global Constraints

- Every change reaches the cluster only by a merged PR to `main`; the agent
  stops at an open PR (CLAUDE.md). One PR per task group below.
- Branch before the first commit; never `--no-verify`. Commit subjects
  ≤ 50 chars, imperative, lowercase, types `feat fix refactor docs chore ops`.
  No `Co-Authored-By`, no generated-with line in commits or PR bodies.
- Names: generated Applications are `<cluster>-<dir>`; the dev cluster is
  registered `name: dev`, label `env=dev`. Destinations match by cluster
  name; the set's template is not edited by this series.
- Secrets are only `<path:kv-<env>/data/...#FIELD>` placeholders (ADR 0004).
  The hub's AVP reads `kv-prod/` and `kv-dev/`; dev's own policy only
  `kv-dev/`.
- Adoption in place: no Application deleted with cascade, no dev workload
  recreated, except dev's hand-rolled monitoring (A4). Dev's Application
  files drop `finalizers:` in git before anything else (A2), because
  `root-dev` selfHeal restores a hand-patched finalizer (#107).
- Dev's application controller is stopped before the A3 merge and is never
  left scaled to 0 without the uninstall that follows; apps otherwise sit
  `Unknown` with CLI 504s.
- Dev keeps kubeadm on Ubuntu. Dev VMs end at 3G control plane + 3G worker,
  `disk_size` 30G (only goes up).
- Renaming or removing a Terraform module needs the plan summary read
  before apply; a `destroy` not intended is a stop (ADR 0013).
- Operator steps (ansible, terraform apply, kubectl on the clusters) run
  from the owner's Mac, not this box; commands live in `docs/runbooks/`
  and the PR checklists link them (ADR 0025). The owner pastes output.
- Hash and htpasswd lines come from `argocd account bcrypt`, never
  `htpasswd`.
- The jobboard dump goes to the workstation, never `nfs-01`.

## Review Focus

Failure modes the spec implies that no task test exercises directly. Each
has a pinning check in the task named.

1. A rendered name or selector label differs from the live one, so the
   adopted DaemonSet or Deployment is recreated or hits an immutable
   field. Pinned by diffing the kustomize render against the old Helm
   render, Task 5.
2. Dev's controller still runs at the A3 merge and fights the hub over the
   tracking-id. Pinned by the cutover runbook's gate, Task 7.
3. The dev entries for the new monitoring apps arrive while the old
   `monitoring` namespace exists, so the set creates into a namespace
   about to be deleted. Pinned by keeping those entries out of A3 and by
   the runbook's order, Tasks 8 and 9.
4. The dev Secret's placeholder `server` trips the appset check or renders
   empty when Vault is sealed. Pinned by the check's fixture, Task 1, and
   `vault status` first in the runbooks.
5. The hub controller's memory climbs once dev is cached and the API
   server falls over, as prod cp1 did at 2 GiB. Pinned by the gate in the
   registration runbook, Task 2.
6. The cert-manager `startupapicheck` hook wedges the first hub sync.
   Pinned by the runbook step naming `terminate-op` then `sync`, Task 7.
7. Remote-write batches exceed the receiver's body limit and fail with 413
   while small writes work. Pinned by `verify-dev.sh` sending a real
   write, Task 12.
8. A stale token stays in Vault after a dev rebuild, so the hub shows dev
   `Unknown`. Pinned by re-running the registration play, Task 2.
