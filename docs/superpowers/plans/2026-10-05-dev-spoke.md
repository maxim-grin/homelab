# Dev Spoke Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking. Per CLAUDE.md, this plan
> records decisions, files, order and checks, not finished code: the
> implementer writes the code. Exact values stay verbatim.

**Goal:** Dev becomes a spoke of prod's ArgoCD, and is rebuildable from
scratch with one Terraform apply, one bootstrap playbook and one
registration playbook.

**Architecture:** One ApplicationSet per app, cluster generator selecting
by the `env` label on declarative cluster Secrets, names `<cluster>-<app>`.
Dev's own ArgoCD is retired. Dev's Prometheus runs in agent mode and
remote-writes to prod. Series A converts dev in place; series B rebuilds it.

**Tech Stack:** ArgoCD ApplicationSets, argocd-vault-plugin (AVP),
kube-prometheus-stack, Terraform (`telmate/proxmox` 3.0.2-rc10, native
`terraform test`), Ansible, kubeadm, Vault.

**Spec:** [2026-10-05-dev-spoke-design.md](../specs/2026-10-05-dev-spoke-design.md)

## Global Constraints

- Every change reaches the cluster only by a merged PR to `main`; the agent
  stops at an open PR (CLAUDE.md). One PR per task group below, not one
  PR for the plan.
- Branch before the first commit; never `--no-verify`. Commit subjects
  ≤ 50 chars, imperative, lowercase, types `feat fix refactor docs chore ops`.
  No `Co-Authored-By`, no generated-with line in commits or PR bodies.
- Names: ApplicationSets produce `prod-<app>` and `dev-<app>`. Clusters are
  registered with `name: prod` (the in-cluster, `https://kubernetes.default.svc`)
  and `name: dev`, labelled `env=prod` / `env=dev`. AppProject destinations
  match by cluster `name`.
- Secrets are only `<path:kv-<env>/data/...#FIELD>` placeholders (ADR 0004).
  AVP in prod ArgoCD reads both `kv-prod/` and `kv-dev/`; spokes read only
  their own.
- Plain Applications that stay plain: `root-prod` (`app-of-apps.yaml`) and
  `argocd-config`. Everything else becomes an ApplicationSet.
- Prod Applications are deleted and recreated; no valuable data on prod
  (owner, 2026-10-05). Production Let's Encrypt allows five duplicate
  certificates per week, so any step that recreates cert-manager is
  rehearsed against `letsencrypt-staging` first.
- Dev keeps kubeadm on Ubuntu. Dev VMs end at 3G control plane + 3G worker,
  `disk_size` 30G (only goes up). `claude-code` is already 4 GiB (#100).
- Renaming or removing a Terraform module needs the plan summary read
  before apply; a `destroy` not intended is a stop (ADR 0013).
- Operator steps (ansible, terraform apply, kubectl on the clusters) run
  from the owner's Mac, not this box. The plan gives commands via the
  runbooks; the owner pastes output.
- The jobboard dump is a hard prerequisite of cutover (Task 11). It goes
  to the workstation, never `nfs-01`.

## Review Focus

Failure modes the spec implies that no task test exercises directly. Each
has a pinning check in the task named.

1. Two sets generate the same Application name (`dev-nfs` from two
   files). Pinned by the render check, Task 1.
2. A set's `selector` matches zero clusters, so the Application silently
   never exists. Pinned by the render check asserting each set yields at
   least one Application, Task 1.
3. A misplaced key inside `template.spec` is ignored silently. Pinned by
   the existing strict schema check extended to sets, Task 1.
4. Remote-write batches exceed ingress-nginx's default 1m request body
   and fail with 413 while the endpoint "works" for small writes. Pinned
   by the verify script sending a real write and checking a series, Task 5
   and Task 14.
5. Sealed Vault leaves every AVP app `Unknown` with health `Healthy`;
   cutover proceeds on a false green. Pinned by `verify-dev.sh` printing
   `vault status` first and by the cutover runbook's gate, Tasks 11 and 14.
6. The cluster Secret's token is rotated or the dev cluster rebuilt and
   the old token stays in Vault, so prod's ArgoCD shows dev
   `Unknown` with a stale credential. Pinned by re-running the
   registration play and `argocd cluster list`, Task 6.
